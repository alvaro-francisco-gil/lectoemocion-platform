# World art provenance

Art for the world screen — the hub where a child picks a resource — and the
letriestrella a chapter pays out.

Generated by `scripts/import-world-art.mjs`, which takes the source an adult
supplied and emits the committed file. Re-run it to reproduce one; do not add
art here by hand.

**The two star sources are named for the wrong letters.** `LETRI-I.svg` draws
a U and `LETRI.U.svg` draws an I. The table above pairs each committed file
with the source that actually contains it, which is why those two rows look
transposed. They are not.

Five further scenes were supplied and are deliberately not here: they are
near-duplicates of `1`, `4`, `7`, `10`, and `12` respectively, distinguishable
only at full size. A sixth picture nothing points at is weight shipped to a
classroom panel over a school network, and
`apps/player-web/src/world/vocabularyAssets.test.ts` fails on one.

`granero.webp` and `bosque.webp` were removed when the world stopped being two
places with a backdrop each. The world screen's background is now a flat colour
in `src/styles.css`, so there is no backdrop art left to account for. The
importer still supports `--scene`; nothing currently uses it.

## Source and rights

The repository owner supplied every source here and attests it is theirs to
ship. As with `../vocabulary/`, no per-file licence identifier was recorded; if
an image is ever challenged, the remedy is to replace the file and re-run the
importer.

Every subject here is drawn. None is a photograph, none depicts a real
person, and none carries child data. Note that this is generated *art*, not
generated *content* — the product ships no AI-generated words, pictures of a
child, or gameplay; see `AGENTS.md`.

## Processing

None of these sources was vector art. Each was an SVG acting as a container
for embedded rasters — `duende.svg` wrapped a single 1122×1402 JPEG, the eight
scenes stack four to fourteen PNGs apiece, and each star is one JPEG with its
vowel drawn as a vector path beside it. Base64 inflates all of that by about a
third: the eight scenes arrived as 30 MB and are committed as 264 kB.

The importer **renders** every such container rather than unwrapping it, even
the single-raster ones. Unwrapping is only sound when the SVG adds nothing to
the image inside it, and that is not something the file announces. Lifting the
raster out of each star produced five identical stars with no letter on them —
not an error, a plausible wrong picture — which is the case that settled it.

A character is then offered the matte in `scripts/lib/remove-white-background.mjs`,
shared with `import-vocabulary-images.mjs`. It grows a transparent region
inward from the border and stops at the dark outline these cartoons are drawn
with, so white *inside* a drawing — the elf's eyes, the gloss on a star —
survives; and it declines any picture whose border is not a flat card, so the
eight scenes, which arrived cut out, pass through untouched. The render is
trimmed of its transparent margin first, or a card drawn inside a larger
document never reaches the border for the flood to find.

Each file is then trimmed to its subject, resized to fit within 512×512
without enlargement, and encoded as WebP at quality 82. A character that comes
out fully opaque fails the import: it is a subject still standing on a card,
and the symptom on the map would be one white rectangle among ten cut-outs
rather than an error anybody sees.

Unlike `../vocabulary/`, nothing here is passed through
`scripts/lib/normalise-ink-area.mjs`. That normaliser equalises the ink of
single objects so a chick and a whale read as one set; these are compositions
that fill their own frame, and equalising them would shrink a fence to the
visual weight of a bee.

No source file is committed. Each is strictly worse than the file beside
it in every dimension, and keeping both would leave two answers to "which one
does the player use". One consequence is worth stating plainly: because the
sources are not here, re-running the importer reproduces a committed file only
for whoever still holds the source it names.

## Why this directory carries a PROVENANCE.md

`scripts/check-privacy.mjs` requires one beside any photographic, audio, or
video file, so that an undocumented one is visible as either a privacy incident
or an asset whose usage rights nobody recorded.
